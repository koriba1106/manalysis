# ムーブ解析by武庫 Web版 v4.2.0(GitHub Pages / ブラウザ完結)

クライミング動画から骨格・ホールドを検出し、ヒールフック／キョン／クロス／フラッギング／ダイアゴナル(カウンターバランス)で
自動停止する解析動画(MP4)を作ります。**サーバー不要**。GitHub Pages に置くだけで動き、
動画は利用者のブラウザ内だけで処理されます(どこにも送信されません)。

## v4.2.0 の変更点: ムーブ判定の再構成

「実際の動画で通常登攀しか出ない」ことへの対応です。判定部分(`docs/js/core.js`)を作り直しました。

- **感度の選択**(既定は **ゆるめ**): 標準(従来) / ゆるめ / かなりゆるめ
- **揺らぎに強い確定**: 従来は「同じ判定が途切れず N フレーム続く」必要があり、骨格がしきい値付近で 1 フレーム揺れるだけで数え直しだった
- **見えなさへの耐性**: 信頼度の下限を胴体と手足で別にし、一時的に下がった関節は直前の位置で補う
- **横向きでもフラッギングを評価**(足の開き具合は向きに依らないため)
- **判定の診断**: 結果欄の「判定の診断」で、なぜムーブが出ないかを自分の動画のデータで確認できる

→ 詳細は下の「ムーブ判定の再構成」。

## ムーブ判定の再構成(v4.2)

### 構造
各ムーブを「名前付きの条件の並び」(ルール表、`RULES`)で宣言しています。評価の順序と、標準の設定での出力は従来と
**完全に同じ**です(Python 版を正解にした照合テストで確認)。条件ごとに「余裕(正=成立、負=不足)」を数値で出せるため、
診断やしきい値の調整に使えます。

### 感度(画面の「ムーブ判定の感度」)
| | しきい値 | 信頼度の下限(胴体/手足) | 一時的な見えなさ | 確定 |
|---|---|---|---|---|
| 標準(従来) | 従来どおり | 0.65 / 0.65 | 補わない | 連続 N フレーム |
| ゆるめ(既定) | 緩和(下記) | 0.5 / 0.4 | 0.3 秒は直前の位置で補う | 直近の N/0.7 フレーム中 N フレーム |
| かなりゆるめ | さらに緩和 | 0.4 / 0.3 | 0.4 秒 | 直近の N/0.6 フレーム中 N フレーム |

「ゆるめ」の主な緩和(骨盤幅=1、角度は度。標準→ゆるめ): ヒールフックの踵の高さ −0.1→−0.5、膝の角度 40〜105→30〜125 /
フラッギングの横への出 2.2→1.5、足の開き 55→35、膝の角度 160→145 / キョンの外への出 0.5→0.3 /
クロスの中心線越え 0.5→0.3。値は `docs/js/core.js` の `SENSITIVITY` で、すべて確認・変更できます。

※ これらの値は、判定の考え方(手足の姿勢が条件の「すぐ手前」で終わる、骨格が揺れる、一部が見えない)から決めたもので、
  実際のクライミング動画で調整したものではありません。**緩めるほど、普通の動きをムーブと誤認しやすくなります**
  (テストでは、ぶら下がり・片手を伸ばす・ハイステップ・足を少し開く、が「ゆるめ」でも通常登攀のままであることを確認)。

### 判定の診断(結果欄の「判定の診断」)
動画ごとに、次のことを数値で見られます。ムーブが出ないとき・誤検出が多いときに開いてください。

- 骨格が使えたフレームの割合と、使えなかった理由(モデルが検出なし / 胴体の信頼度不足 / 別人として除外)
- 体幹が見えた割合、左右の軸が使えた割合(横向き・ねじりが多いと低くなる)
- 関節ごとに見えていた割合
- ムーブごとに、判定できたフレーム数・成立数・見えない/横向きで評価できなかった数、
  **「あと1〜2条件で成立していたもの」と不足の大きさ**(例: 足の横への出が中央値で 0.20 不足)
- 診断に基づく助言(撮り方の改善、感度の変更)

## 公開手順(GitHub だけで完結)

1. このフォルダの中身を新しいリポジトリのルートに push する(`docs/` `.github/` `scripts/` `tests/` `reference/` ごと)
2. リポジトリの **Settings → Pages → Build and deployment → Source を「GitHub Actions」** にする
3. `main` に push すると `deploy-pages` が走り、テスト通過後に公開される
4. `https://<ユーザー名>.github.io/<リポジトリ名>/` を開く

Actions で公開すると、骨格推定モデルを検証のうえサイトに同梱します(初回読み込みが自サイト内で完結)。
Source を「Deploy from a branch(`/docs`)」にしても動きますが、その場合モデルは Google の配布 URL から読み込みます。
ローカルで試す: `python3 -m http.server 8000 -d docs` → http://localhost:8000(`file://` では動きません)

## カウンターバランスの判定

作者の元コードでは、カウンターバランスは「ダイアゴナル(カウンター)」の動きとして扱われています。従来の対角判定は
「足首が腰よりかなり低い」ときしか成立せず、**逆の手を高く伸ばして逆の足を横へ出す姿勢**は条件を外れて
フラッギングに落ちていました。そこで、ダイアゴナルを緩めた判定をフラッギングより先に評価するようにしました。

- 成立条件: 片手が高く(腰基準 2.0 以上)、もう片方の手はそれより 0.6 以上低い / 逆側の足がほぼ伸びていて
  (140°以上)腰より下(−1.0 以下)、体の中心から 1.2 以上、逆側へ出ている / 手と足が横方向に 1.5 以上離れている
- 表示名は「右手ダイアゴナル(カウンターバランス)」(左も同様)。強い条件で成立した従来のダイアゴナルも同じ名前
- 両手が同じ高さの純粋なフラッギングは従来どおり。画面の **「カウンターバランスをフラッギングと区別する」** を
  切ると、従来の挙動に戻せる
- しきい値は `docs/js/core.js` の `counter_*`(Python 版 `reference/muko_engine.py` も同じ値)

※ 実際の動画で意図と違う判定が残る場合は、そのフレームの姿勢(静止画)を元にしきい値を調整できます。

## 高速化

| 内容 | 効果 |
|---|---|
| 骨格推定に渡す画像を、動画から必要な範囲だけ縮小して作成(設定で 512 / 768 / 1280px) | 本物の MediaPipe(CPU)で推論が **約 15〜24% 短縮**(フルHD、実測) |
| 動画要素を 2〜4 個持ち、先のフレームを並行してシークしておく(解像度が大きいほど控えめ) | 複数コアの端末で動画待ちを隠す(※下記) |
| 作業キャンバスの読み戻しをやめ、服の色分布は胴体領域だけ(最大48px)で計算 | 色分布の計算が 1 フレーム 2ms 前後 |
| 各段階の所要時間をログに表示(動画待ち / 描画 / 推論 / 色分布 / 判定 / 重ね描き / 符号化) | ボトルネックを自分で確認できる |

※ 計測した環境は **CPU 1 コア・ソフトウェア描画** のため、先読みの並列化の効果は測れていません。この環境では
全体の処理時間は、動画のシーク待ち(1 フレーム 50〜90ms)が支配的でした。連続再生で読み出すと約 3 倍速い
ことを確認していますが、タブが裏に回ると止まる・ブラウザ差が大きいため採用していません。
さらに速くするなら WebCodecs の VideoDecoder による連続デコード(MP4 のみ・要デマルチプレクサ)が次の選択肢です。
速さを優先する場合は「推定精度」を下げる、「出力の最大サイズ」「推論の画像サイズ」を小さくするのが確実です。

## セキュリティ

詳細は `SECURITY.md`。主な内容: CSP(インライン・eval 不可、読み込み元を自サイトに限定)、他サイトへの埋め込み禁止、
XSS 対策、巨大入力の上限(4K・2 時間・出力サイズ)、依存の固定とロックファイル、同梱ライブラリのハッシュ検証、
`npm audit`、Dependabot、CI の最小権限。GitHub Pages ではヘッダを付けられないため CSP は `<meta>` で指定しています。

## 対応ブラウザ

動画のエンコードに WebCodecs を使います: PC の **Chrome / Edge**(MP4=H.264 で出力)、**Safari 16.4+**。
Firefox などは WebM(VP9) で出力される場合があります。HTTPS か localhost が必要です。スマホは動作しますが遅く、メモリも使います。

- `counterbalance.test.js`: カウンターバランスがフラッギングにならない回帰テスト(修正前の誤判定の再現を含む)

  `e2e_theme.py`、`e2e_counter.py`(チェックボックスの配線)、`e2e_sensitivity.py`(感度と診断パネル)、`bench.py`(速度計測)、

## 見た目のカスタマイズ(CSS)

見た目は `docs/css/theme.css` の変数を書き換えるだけで変えられます(HTML・JS の修正は不要)。

```css
:root {
  --color-accent: #2b8a3e;     /* 強調色: 主ボタン・進捗バー・ムーブ時刻 */
  --color-roi: #2b8a3e;        /* クライマー範囲指定の枠 */
  --radius-card: 4px;          /* カードの角丸 */
  --font-size-title: 28px;     /* ページ見出しの大きさ */
}
```

画面右上の「表示」で 自動(OS 設定に追従)/ ライト / ダーク を切り替えられます。解析結果の**動画に焼き込まれる**文字・赤丸・
骨格線の色は CSS では変わりません(`docs/js/render.js`)。CSP により `<style>` の直書きやインライン style は使えないため、
変更は外部 CSS ファイルで行ってください。

## 制限・注意

- 動画の読み込みはブラウザが再生できる形式に限る(mp4/H.264, webm など)。iPhone の HEVC(.mov)は
  Windows の Chrome では再生できないことがある
- 出力は長辺 1920px までに縮小(設定で変更可)。音声は従来どおり付かない。出力はメモリ上で組み立てる
- 骨格推定は MediaPipe の新 API(Tasks)。従来版の `mp.solutions` とは数値が微妙に異なる場合がある
